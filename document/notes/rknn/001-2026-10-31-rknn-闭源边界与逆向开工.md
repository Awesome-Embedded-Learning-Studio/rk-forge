## 1. RKNN 是什么（一句话）

Rockchip NPU 的模型格式 + 软件栈名：`训练模型 → ONNX → rknn-toolkit2(PC,闭源) → .rknn →
librknnrt.so(板端,闭源) → 内核驱动(GPL) → NPU 硬件`。类比 TensorRT/OpenVINO。

## 2. 闭源边界（本地取证）

| 件 | 状态 | 本地位置 |
|---|---|---|
| librknnrt.so 1.5.0（e6fe0c678@2023-05-25，4.8MB） | ❌ 闭源（librknn_api.so 只是它的 symlink） | `reference/rk3588/external/rknpu2/runtime/RK3588/Linux/librknn_api/aarch64/` |
| rknn-toolkit2（PC 端编译器） | ❌ 闭源（仓库里只有 PDF 手册） | 无本地件 |
| 内核驱动 drivers/rknpu | ✅ GPL-2.0 全源码（写自 5.10.198） | `reference/rk3588/kernel/drivers/rknpu/`（内含 .o 残留要清） |
| rknn_api.h / rknpu_ioctl.h | ✅ 开放——逆向用户态的两本字典 | 同上两处 |
| 我们 out/rk3588-topeet | 无任何 rknn 件（rootfs/内核均未接） | — |

内核驱动不懂神经网络，只管 GEM 内存/IOMMU/提交/fence/devfreq；网络→NPU 指令的编译在 PC 端完成。

## 3. 社区开源栈（2026-10 现状）

- **rocket 驱动已进主线 6.18**（我们 7.1 树里有，CONFIG 未开 = sdk-diff Phase 6 TODO）；
  用户态 = **Mesa Teflon**（TFLite delegate，Mesa 25.3+，`-Dgallium-drivers=rocket -Dteflon=true`）
- 限制：仅加速 INT8 per-tensor 卷积（其余 CPU 回退）、时钟锁 200MHz、单模型单核、reset 不可靠
- 社区没逆 librknnrt——Tomeu Vizoso/Collabora 是**正向重写**绕开 .rknn 生态走 TFLite

**两条测试路线**：A = vendor 移植（7.1 断点：`.gem_free_object_unlocked`/`.gem_prime_export` 已删，要迁
drm_gem_object_funcs；DT 要补 vendor 单节点，与主线 3 节点冲突）；**B = 主线 rocket+Teflon（推荐先测，
零 blob：主线 dtsi 节点现成 + NPU 供电轨 rk860x 已移植 patch 0004）**。

## 4. 社区 RE 弹药（GitHub 调研 + 本机验证）

- **Netron `source/rknn.js`** = .rknn 容器完整规格：1.5.0 时代 = 头 + 内嵌 blob + **明文 JSON 图段**

- **mtx512/rk3588-npu**（132★，GPL-3）= 绕开 librknnrt 自写命令流，llama2.c TinyStories 跑上 NPU——
  证明 C++/C 开源引擎终点可达；NPU 架构 ≈ NVDLA（博客 jas-hacks）
- **blob 自吐开关（本机 strings 已验证！）**：Linux 环境变量 `RKNN_LOG_LEVEL` / `RKNN_DUMP_DIR` /
  `RKNN_DUMP_TXT_TENSOR` / `RKNN_DUMP_QUANT`——blob 自吐每层中间张量，可当对拍 oracle

## 5. 定案

1. **技术路线**：C++ 写中间层，铁律 = 对外 C ABI（extern "C" 包 rknn_api.h 兼容壳，drop-in 替换）。
   分层 = C 壳 → loader(.rknn JSON→图 IR) → memory planner(RAII 管 6 buffer) → 命令流 emitter
   (span+bitfield) → driver client(ioctl)。差异化护城河 = RKNN_DUMP_TXT_TENSOR 逐层金标准对拍。
   工具层（dumper/胶水）仍 Python（no-shell-scripts 纪律）。
2. **逆向工具阵**：主伞 = REA（morluto/rea，MCP+CLI，「理解→证据→重实现」，Node 26 本机已满足）；
   深度分析后端 = Ghidra 12 + Java 21（装机中）；可选 ReVa（cyberkaida Ghidra 专用 MCP）；
   dsh headless = 副分析（deepseek-flash + reasoning high，思考链打 stdout，已验通）。
3. **P0→P3**：P0 = .rknn dumper（照 Netron 抄 Python，先用 toolkit2 1.5.0 转 1-2 个测试模型）→
   P1 = API→ioctl 映射（C harness + strace + RKNN_LOG_LEVEL）→ P2 = 命令流（NVDLA 参照 + mtx512 +
   DUMP 对拍）→ P3 = CPU fallback 算子。
