# 内容与站点规划

> 管的是「怎么写、写成什么样、站点怎么摆」——课程主线仍是[三线分册](index.md)，本文件承接内容体验设计的承重部分：写作管线、体验机制、选题池与站点信息架构。

## 1. 写作管线（阶段二开写第零步）

- 正文一律走 content_forge 编辑闭环：全文改写（完整文件为最小单位）+ 声音/保真/连续性/指代四道独立走查 + `humanizer_lint`（04-tutorial 教程六规则，全 error 级），用户验声通过才算终稿；
- **第零步**：动笔第一章之前，先把老规划 11 节叙事模板与 04-tutorial 六规则合并成唯一正文模板，冻结后再开卷——两套骨架并存必然漂移；
- 章节级验收单纪律：每章动笔前先列依赖清单与验收单（对应能力与证据口径），写完对照收口；任务卡机制（见下）在模板合并时决定取舍。

## 2. 体验机制五件套（每篇可用）

| 机制 | 一句话 | 形态 |
|---|---|---|
| 任务卡 | 开篇八字段：目标/预计用时/难度/环境/前置/本章故障/成功画面/证据 | 开头表格 |
| 故障档案 | 真实事故按「案发现场→嫌疑人→证据→推翻→定案」结构还原推理过程 | 排障小节 |
| 证据卡 | 状态/板卡/内核/证据/复现入口/已知边界六行，贴在能力结论旁 | 章尾卡片 |
| 故障注入 | 每篇至少一个安全可复现的坑，让读者亲手制造再定位 | 动手小节 |
| 无板体验 | QEMU 入口「没有板也能玩」，配边界声明：仿真证明软件控制流，不证明时钟/电源/PHY/DDR/显示时序 | 独立入口 |

## 5. 北极星五问

首页成功的判据——第一次来的读者十分钟能回答：

1. 没有开发板，我现在能运行什么？
2. 我想学通用 bring-up 方法，应该从哪里开始？
3. 我手上正好有 RK3506B/RK3568/RK3588，哪条路线最值？
4. 一个教程结论背后有哪些真实证据？
5. 我完成什么实验后，能明确说自己掌握了一项能力？

首页只能告诉读者"我们规划了很多章"而不回答这五问，内容就还只是丰富在仓库内部。

## 6. 节奏沿革

老规划的 S0-S4 推进顺序（对账 → Base 总纲 → 四篇样板 → 项目与 12 篇 → 公开导航）已被三线分册 + 阶段二开写节奏取代：对账与 Base 承接已随 2026-10-25 合并完成，样板与体验篇从阶段二写作面里自然产出，站点 IA 在内容成型后实施。
