### 第 1 章：从训练模型到 RKNN

一句话：训练好的模型怎么变成 NPU 能跑的东西——PyTorch → ONNX → RKNN 三层翻译，**版本配对是本方向的命门**。

要点：

- 三层关系：训练框架 → 中性图（ONNX）→ 硬件专属格式（RKNN）；与 TensorRT/OpenVINO/CoreML 同构
- host 工具（rknn-toolkit2）产 `.rknn`、板端 runtime（librknnrt）执行；**转换产物与 runtime 版本必须严格匹配**——「代码没动就跑不了」的头号真因
- 输入输出 layout（NCHW/NHWC）与数据类型（FP32/INT8/FP16，性能差一个量级）；输出 shape 决定后处理写法
- 算子支持提前查：不支持时拒绝转换 / 回退 CPU（性能塌陷）/ 近似实现（精度变化）；四种工程手段（等价算子替换、后处理剥出、模型重写、参考模型起步）
- 四层依赖链（toolkit → .rknn 格式 → runtime → 驱动 → 固件）：固定配对版本当基线，升级必做前后精度+性能对比

实践：
- 小模型全链转换（MobileNetV2/YOLOv5nano），每步存中间产物
- 板端输出与 host ONNX 输出比对（cosine similarity）；记版本基线
- 故意做一次版本错配，建「错配症状库」

### 第 2 章：FP16/INT8 与校准

一句话：量化省 4 倍体积几倍速度，代价是精度——怎么把损失控制住、怎么判定「量化后还能用」。

要点：

- 为什么 8bit 够用：权重激活多呈钟形分布；对称（权重）/非对称（激活）映射；outlier 与 attention softmax 是敏感点
- **校准集决定量化质量**：要覆盖真实推理分布；min-max/percentile/KL 散度等方法的取舍；100-1000 张典型量
- 精度判定要有量化标准（top-1/mAP/mIoU/cosine）；分类掉 0.5-2%、检测掉 1-3 点常见；**关键层保精度 = 混合精度**
- 收益是全方位的：大小/带宽/延迟/功耗叠加，产品级几乎都走 INT8
- 不支持算子的决策树：查矩阵 → 算子替换 → CPU fallback（测过可接受）→ 模型重构 → 换模型

实践：
- FP16/INT8（两种校准）三版本对比精度/大小/延迟/功耗
- 故意改坏校准集再回归，看修复幅度
- 量化敏感层保 FP16 的 trade-off；不支持算子的两种处理对比

### 第 3 章：输入、推理与后处理

一句话：真正跑一次推理——预处理的三个坑、同步异步的选择、后处理这段 CPU 代码写好坏差很多。

要点：

- 预处理三坑：resize 用 RGA 零拷、letterbox padding 值与训练一致、**很多 INT8 模型把 normalization 折进量化参数**；BGR/RGB 必须与训练一致
- NCHW vs NHWC：转换是 transpose 有开销，让采集/RGA 直接输出目标 layout
- 同步（简单、NPU 闲置）vs 异步（吞吐高、代码复杂）：**原型期同步、优化期异步，先测同步基准**
- 多输入要等齐再提交；输出常落 dma-buf 可零拷贝消费，别养成「取回 CPU 再处理」的习惯
- **NMS 是 CPU 任务，写得好坏直接吃延迟**；后处理慢于推理时 CPU 是瓶颈
- 资源生命周期：context/model/buffer 启动建一次长期复用；销毁有顺序；任何「越跑越慢」都是生命周期 bug

实践：
- 写**不依赖厂商 demo 外壳**的独立推理程序
- 100 次推理分解各级耗时找瓶颈
- 制造错误输入建「症状库」；1 小时长跑看泄漏出稳定性报告

### 第 4 章：实时 AI 流水线

一句话：把采集、预处理、推理、后处理、显示拼成「摄像头 → 检测 → 画框 → 显示」的完整实时链。

要点：

- 采集线程只管搬 dma-buf 别做像素处理；源抖动会传全链
- RGA 一次做完 resize+CSC+letterbox；**dma-buf 全程流转、物理拷贝次数理想为 0**——警惕 runtime 内部 fallback 的伪零拷贝
- 模型实例启动加载一次长期复用；单帧失败记日志丢帧继续，不杀进程
- 显示三种合成策略（CPU 画框 / DRM overlay / GPU）；检测框要用 V4L2 timestamp 关联对应帧
- backpressure 策略（丢老帧保实时 vs 排队保吞吐）；端到端延迟典型 30-80ms，**先量主瓶颈再针对性优化**

实践：
- 端到端实时检测稳跑 30 分钟以上
- ftrace/perf 分解每帧各级延迟
- 优化一个真实瓶颈并做 A/B 对比；制造负载压力测 backpressure 策略

### 第 5 章：从 demo 到 AI 服务

一句话：跑通 pipeline 是 demo，「能长期跑、多客户端调用、温度高时还能用」才是服务。

要点：

- 多模型调度三策略（串行/并行/流水）；NPU 内存有限，权重大时按需加载卸载；优先级分级
- 多 NPU core：单大模型用满多核 vs 多小模型分散并发；core 亲和性要实测
- 任务队列 + HTTP/gRPC 把板上 NPU 变成局域网 AI 服务；最优并发度要测
- 监控三级指标（服务 QPS/延迟、NPU 占用/温度/降频、业务准确率），必须可视化
- **thermal 降级策略：温度高时变慢而不是 crash**；降频时降帧率/换小模型；温度回落自动恢复，卡死在低性能是 bug
- 异常恢复三级：单帧错误丢帧继续、进程崩溃守护重启、设备故障降级 CPU 推理；7×24 长稳测试

方向产出：完整流水线、精度报告、性能报告（p50/p99、长稳）、服务化形态（接口+监控+恢复）。
