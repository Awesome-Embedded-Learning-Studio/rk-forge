## 根因与改动

此前 GEM 装配与 query 对拍并不等于完整执行链通过。own 将整个 A/B/C
计划直接一次提交，随后只补终端 CPU Reshape；没有按 CPU 边界、预载任务
以及独立选核计划的 PC 模式边界拆分执行。

- **dualout**：`outputs_get` 仍限制 `n_outputs == 1`。现按每个 output index
  选取其独立 GEM，剥除 NC1HWC2 padding 后返回逻辑 NCHW，支持 FP16/int8
  原始输出、float 转换与 prealloc。全部校验完成后才写用户 buffer，拒绝
  重复/越界 index 和不足容量，分配失败时释放本次已分配部分。
  图中的 cls Reshape 在 feat 的后续 NPU 段之前执行，与 vendor 的两段提交一致。
- **mbv3s**：HardSigmoid 有附加常量/LUT 预载任务，vendor 用独立
  `flags=0x1` 提交，普通 PC ping-pong 段用 `flags=0x5`。own 一次连跑会在
  第一组五个普通任务之后进入不正确的预载执行路径并超时。
  现按图顺序分成 57 次提交，同时执行分类尾部的 CPU Reshape；没有延长超时。
- **shufflenet**：图中 16 次 CPU Transpose 及其后 Reshape 原先被跳过。
  现解析 Transpose 属性表中的 permutation，按源/目标布局取回、转置、重新
  打包，在 NPU 段之间同步并执行。7×7 的 blocked 特征面有四位置对齐，
  49 个有效位置对应 52 个物理位置，并清零空间/通道 padding。
  source 与 destination 可复用同一 activation 分配，先完整 gather 再写回。

执行时在 CPU 操作前等待前一 NPU 段完成，对源和目标执行 FROM_DEVICE，
CPU 写入后对目标执行 TO_DEVICE。未知 CPU 算子、无效 shape/permutation、
越界映射和同步/提交错误直接返回，后续任务停止。

显式选核还补齐了单核 A 段的实际 lane、B/C 计划中的单核 fallback、
Concat/copy 与普通链的 PC mode 切换、五组 subcore ABI 字段及逻辑 task_start。
这些参数由图和现有 task 表推导，不按模型名或固定层号选择。

主要源码现位于 `src/rknpu/rk3588/src/execution.cpp` 与 `tensor.cpp`，
分别处理执行调度和张量变换；loader.cpp 与 model.h 解析 Transpose permutation。
内部接口位于 include/，不引入新的公开 ABI。构建和测试入口见运行时 README。
