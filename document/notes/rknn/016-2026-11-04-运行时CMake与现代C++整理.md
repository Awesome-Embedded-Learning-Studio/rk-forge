# 运行时 CMake 与现代 C++ 整理

自研用户态运行时统一位于 `src/rknpu/rk3588/`，回归、板验和证据复核工具
位于其 `tests/` 子目录。旧 `.claude/rknn/engine/`、根目录下的
`tests/rknpu/rk3588/` 及 Python 运行时构建入口已删除，不保留兼容入口。
编译产物和测试证据仍写到 `out/rk3588-topeet/`。

构建改用 CMake 3.20+、C++20，提供 AArch64 toolchain、安装、原生 CTest、
ASan/UBSan 和 format/format-check 目标。`.clang-format` 原样取自
`~/Cinux/.clang-format`，实际使用全局 clang-format 18.1.3。
命令及外部输入配置见 [运行时 README](../../../src/rknpu/rk3588/README.md)。

主要整理包括：

- execution.cpp、tensor.cpp 与 shell.cpp 分别承载执行调度、张量处理和
  RKNN C ABI；原先包含实现头文件的方式改为独立编译、直接链接生产对象。
- 具名 BufferSlot、TaskRange、TaskRecord 和 ioctl 请求结构替代数字角色及
  手工字节拼接，静态断言验证 legacy ABI 的大小与关键偏移。
- 使用 span、array、optional 和 bit_cast 表达缓冲区、固定数组、待提交状态
  及浮点位表示；保留量化、舍入和禁止浮点收缩的规则。
- 上下文、FD 和待移交输出采用 RAII；mmap 失败释放已创建 GEM；初始同步及
  输入同步错误向上传递；fence 等待使用有限截止时间，并返回超时和设备错误。

本次主机验证通过，完整入口为 `tests/run_host.py --suite all --sync-evidence …`。
统一报告：`out/rk3588-topeet/rknpu-tests/host-run.io1zu77f/verification.json`。

ASan 设置 `detect_leaks=0`。QEMU 模拟设备，不执行 NPU 算术；本次没有连接、
重启或烧写板卡，也未替换 NFS 中已验收的运行库。新库仍需实板复验，不能把
重构前的九模型实板 PASS 直接当作本次构建的硬件验收。
