# Note 109 · panthor M2n：屏幕"竖条纹垃圾"定谳并根修——条带误全屏 + 页表自画像

日期：2026-09-11 · 战役七第二十八篇 · 上一节：note 108（迟发毒根修）

## 0. 摘要

用户质疑截图（"你确定嘛？"）→ MCP 读图定谳：屏上"竖条纹绿紫黑"
不是桌面，是**双 bug 合成的垃圾**。①bg-fallback 单维门（tw≥1024）
把 1027×35 damage 条带当背景 actor 拉伸满屏；②tex_read_px 的 AFBC
body 偏移不校验——mutter 自管缓冲的残留垃圾头（GPU 页表页 PTE）
截 32 位后=小偏移，body=sp+小偏移=**把头区所在的页表页当像素读出自
画像**（屏上高频 007b61=PTE 高位 PA 0x617b000 域、4 连同低字节=
PTE 属性字）。双修后：**253 独立色真壁纸结构化上屏（65%/55% 翻页）**，
受控回归 7/7 绿。

## 1. 取证链（方法：MCP 读图 + 像素行程分析）

- MCP 客观描述=竖直条纹、无界面元素 → 不是"可见桌面"（note 76
  证据门：此前的 56.8%/35 色直方图只证颜色不证内容）
- 像素行程分析定位伪像结构：**16px 横向周期**、近黑字段随 sb 递增
  （000006→8→a→c）、4 连 run 同低字节只变高字节、007b61 高频复现
  → 全部=内存元数据特征非图像特征
- log 反查画屏者：`scanout-mirror 1024x600` ← rjob 采样
  `pending tex=1027x35 ptype=6 stride=410 hdr 全零/垃圾`
  ← `bg-fallback tex=1027x35`（误触发）→ 全屏恒等 quad 拉伸条带
- 同屏顶部 y<128 白底彩字=真渲染文本（351×82 LINEAR 正常路径），
  与垃圾并存=两个写者的活体证据

## 2. 双修

| bug | 修 |
|---|---|
| 条带误全屏 | `tw≥1024 \|\| th≥1024` → `tw≥1024 && th≥256`（真背景 th≥533；条带 th≤100 实测） |
| 页表自画像 | tex_read_px：h04 非 0 且（非 64 对齐 或 ≥64MB）→ 返回 0。自家 body 偏移恒 64 对齐、壁纸 body 33MB 为最大真值 |
