# GPU 用户态收官：QEMU 里的采样合成战役，从满负载黑屏到真壁纸上屏

> [NPU 章](08_npu.md) 把最后一块大件收进了主线，全卷的主线故事到那里其实已经讲完。这一章是全卷的收官章，故事却发生在咱们开发它的电脑里：[GPU 章](04_gpu.md) 章末的旁白提过一条平行的 CSF 研究线，当时的原话是“咱们本章不展开它的战役过程”，本章就是这场战役的完整记录。战场还是 QEMU 里的 RK3588 lite 模拟机，对手却是 GPU 用户态最深处的一层，也就是 Mesa 交给 GPU 的采样合成命令流。战役从 2026 年 9 月 6 日打到了 9 月 12 日，从 [notes/100](../../notes/100-2026-09-06-panthor-m2m-desktop-session-gpulive.md) 一直写到 [notes/116](../../notes/116-2026-09-12-panthor-m2n-wallpaper-visible-achieved.md) 的 17 篇工程笔记，把全程记了下来。起点是模拟机上最拧巴的一种状态：桌面会话在满负载地跑着，屏却始终是黑的。终点则是真壁纸的像素级全屏上屏，而且过了数值与人眼的两段式验收。

## 本章定位：研究线的最后一役，和一份人月级判决

研究线的来龙去脉，GPU 章的旁白只给了两行，咱们这里补齐。8 月底咱们在 QEMU 里搭了一台 RK3588 lite 模拟机，机器本体是 [qemu-sim-machines.patch](../../../sim/qemu-sim-machines.patch) 里的 rk3588-lite.c（如今长到了 6931 行）。QEMU 兼任 BL31 去应答 SCMI 的时钟调用，咱们再给 GPU 造一片寄存器的影子，用一个假 MCU 复刻固件上电后会做的初始化。Panthor（主线里 CSF 时代 Mali 的内核驱动，GPU 章的主角）的 probe 在模拟机里跑通、渲染节点出现，是研究线的第一个里程碑，落在了 [notes/82](../../notes/82-2026-08-31-panthor-m0-scmi-agent.md) 里。Mesa 用户态全链的跑通、renderer 报出 Mali-G610，是研究线的第二个里程碑（[notes/83](../../notes/83-2026-09-02-panthor-m1-campaign.md)）。之后工程日志里的战役七开工，目标是让像素真的从 Mesa 的命令流里流出来：glClear 的清屏（[notes/87](../../notes/87-2026-09-04-panthor-m2c-first-pixels.md)）、结构匹配的 blit、AFBC（Arm 的帧缓冲压缩格式）的读写与 VOP 解码（[notes/96](../../notes/96-2026-09-06-panthor-m2k-afbc-write-and-vop-decode.md)）、常量色 shader 的执行（[notes/99](../../notes/99-2026-09-06-panthor-m2l-constant-fs-executed.md)），一路全走的真数据路径。

当初的裁决还不只给了人月数。M0 的预估是 3 到 6 人周，结果咱们同日就打穿了渲染节点，全链打印与板上的日志逐字一致（[notes/82](../../notes/82-2026-08-31-panthor-m0-scmi-agent.md)）。M1 的预估是 1 到 2 人周，实际也就花了三天（[notes/83](../../notes/83-2026-09-02-panthor-m1-campaign.md)）。裁决同时立了一条纪律：M2 的执行器要过证据门，受控的 PoC 在 4 到 6 周内写不出正确像素，低层仿真的路线就得停（[notes/76](../../notes/76-2026-08-29-mali-csf-emulation-feasibility.md)）。人月数的悲乐观现在回头看都无所谓了，真正管用的是证据门的纪律，它逼着咱们把每一步的宣称都拴在可复现的证据上。

到了 M2l 收官的时候（M 后面的字母是战役的里程碑编号，顺排下来的，链头的 M-pre0 是 M0 之前解除平台依赖的准备段），常量色类的 draw 已经能执行，桌面却还是黑的。挡在前面的，是当初可行性裁决写下的那段话（[notes/76](../../notes/76-2026-08-29-mali-csf-emulation-feasibility.md)），其中一句的原文是“覆盖 GNOME 是 9–24+ 人月级高风险研发”。人月级的判决压着，战役却还是开了打，咱们的武器有两件：受控测试压住已知面，诚实边界圈住咱们的宣称。战役七真像素线的最终链，咱们照 [notes/108](../../notes/108-2026-09-10-panthor-m2n-poison-root-cause.md) 的原样记在下面：

```text
M-pre0 → M0 → M1 → M2a..M2l(shader 语义) → M2m(会话负载) →
M2n：侦察 → 受控 11/11 → 异步化 → 双病分流 → 界内全证 → 壁纸门 →
显示点亮 → 内容工程 → 100% 全屏 → 毒根修+缝合写
```

咱们把两条线摆在一起对照。NPU 章的 qemu 是假内核：qemu-aarch64-static 直接跑的是 ARM64 程序，LD_PRELOAD 的桩库拦下 ioctl，假的是内核那一侧，librknnrt 本身是真的在跑。本章的 qemu 是假硬件：guest 里跑的是真正的 Panthor、真正的 Mesa 与真正的 GNOME，假的只是那颗 Mali-G610，命令流到设备边界才落进咱们的执行器。两条线一左一右地夹住了闭源边界，办法也是同源的。文法从 Mesa 的 v10.xml 与 panthor 源码这类开放材料里读，理解拿 dump 的实测来驱动，验收的判据交给对拍或数值。

本章咱们就按 M2n 这一程的六幕来讲，幕次与笔记的对应关系如下：

- 定界侦察，笔记 100-101
- 执行器实现，笔记 102-103
- 腐蚀追凶，笔记 104-106
- 可见达成，笔记 107
- 散射根修，笔记 108-110
- 校验纪律收官，笔记 111-116

有些边界咱们开场就立好：研究线的产出全部是仿真取证。仿真证明的是软件控制流与协议交互，而时钟、电源、DDR 时序这些硬件行为，它一样都证明不了。真壁纸上屏的判据长什么样，咱们到幕六如实交代。板上主线的验收依据，仍然是 GPU 章的那颗内建固件。两条线各管各的：主线管的是验收，研究线管的是理解。

## 定界侦察：桌面满负载在跑，屏却是黑的

### 会话活了，内容没来

咱们在 M2l 引擎上跑了第一轮 GDM 机检验，它给出了一种自相矛盾的状态（[notes/100](../../notes/100-2026-09-06-panthor-m2m-desktop-session-gpulive.md)）。链上的 M2m（会话负载）到这一轮收官，note 100 文件名里的 m2m 说的就是它：

| 项 | 结果 |
|---|---|
| 会话 | gdm active，nautilus 与 gjs 都活着，是完整桌面而非 greeter |
| GPU 消费 | 4316+ job 持续在跑 |
| GPUBLIT | mutter 负载下活跃，60×60/48×48 的 AFBC 图标与光标搬运 |
| GPUFS | 0，mutter 没有常量色 FS 的 job |
| screendump | 全黑，扫描缓冲被 clear 之后无人写入 |

screendump 是 QEMU 的截屏命令，它的产物是 PPM（无压缩的原始位图，像素的字节直接可读）。表里的 GPUBLIT 与 GPUFS 是 gpulive 观测面上的两个计数器，分别数搬运类与常量色 FS 类的 job。会话在满负载地跑着，搬运倒是没停过，屏却是全黑的，咱们只能往内容来源的方向查。模拟机里的 GPLANES 普查把主合成时刻的批池翻了一遍，想找一张能整块拷贝的全屏背景纹理，结果是决定性的否定：批池里全是 8×11、20×20 级的小匹配，而且多为噪声，没有任何 ≥1024×600 的纹理 plane。GNOME 的桌面并不是一张背景图加几个窗口，它是一堆小 actor（合成器里每个可见的矩形）逐像素采样合成的。所以桌面要可见，剩下的路只有一条：去完整实现纹理的采样合成，恰好就是当初人月级判决说的深水区本体。

### 跟着 SPD 走，采样 shader 全数到手

深水区的水有多深，咱们得量一量才踏实。咱们找对了路：跟着 SPD 的指针走（[notes/101](../../notes/101-2026-09-06-panthor-m2n-sampling-fs-recon.md)）。SPD 是 Shader Program Descriptor 的缩写（shader 程序描述符），里面带着阶段、寄存器配额与二进制地址，文法的权威是 Mesa 的 v10.xml 生成文件。Binary 字段落在字节偏移 +8 的位置，咱们首版误读成了 +0x10，白跑了一段弯路。改对了之后，mutter 桌面合成的采样 shader 指令流全数到手：每次开机数百个 RUN_IDVS 的 4 顶点 quad 直绘，带采样 FS 的占 97%。

这一幕还翻出了一个仪器教训。[notes/100](../../notes/100-2026-09-06-panthor-m2m-desktop-session-gpulive.md) 里咱们记过 RUN_IDVS 等于 0、合成全走 RUN_FRAGMENT，那个读数其实是错的：挂点加读数方法的假象。换 HMP（QEMU 的交互式监视器）里查设备属性的 qom-get 直读计数器，5 分钟里 RUN_IDVS 出现了 587 次，带采样 FS 的有 584 次。桌面黑的真正原因，是采样 draw 的 FS 没人执行，而不是路径没走到。所以仪器读数跟判定一样，都是要被复核的，这一课咱们在幕六还会以更大的代价再上一次。

采样 FS 的形态反倒给了信心，咱们把三类统计摆在下面（[notes/101](../../notes/101-2026-09-06-panthor-m2n-sampling-fs-recon.md)）：

| SPD | 次数 | 指令骨架 |
|---|---|---|
| e5020 | 443 | LD_VAR 插值 → TEX_FETCH 采样 → FMA 调制 → ATEST → BLEND |
| a9b80 | 113 | LD_VAR×4 → TEX_SINGLE×2 → FMA → ATEST → BLEND |
| a9ce0 | 1 | 最简形态，一共 9 条 |

LD_VAR 是从顶点插值取 varying 的指令，TEX_SINGLE 与 TEX_FETCH 是取纹理像素的指令，FMA 做的是乘加，ATEST 管的是收尾，BLEND 管的是把结果混进目标。每个像素的活是仿射 uv 插值加一两次采样加乘加加混合，shader 的本体不超过 16 条指令。深水区比判决预估的 per-pixel shader 窄得多，这就是执行器敢开工的依据。咱们配套的受控测试 [glestexture.py](../../../sim/glestexture.py) 也在这一幕立了起来：2×2 四色纹理加 NEAREST 采样加全屏 TRIANGLE_STRIP，顶点形态与 mutter（GNOME 的合成器进程）的同构。它此刻的形态是 FAIL（采样还没实现），而 FAIL 的基线成了后面每一轮回归的守门员。

纹理与顶点的落点，咱们靠受控测试的 dump 补齐了拼图（[notes/101](../../notes/101-2026-09-06-panthor-m2n-sampling-fs-recon.md)）。SRT（Shader Resource Table、shader 的资源表）的下标就是表号，七张表各管各的资源：

- 0 号表是 UBO（着色器里的常量块）
- 1 号表是 ATTRIBUTE（顶点属性）
- 2 号表是属性缓冲
- 3 号表是采样器
- 4 号表是纹理
- 5 号表是图像
- 6 号表是 SSBO（着色器存储块）

表项指向的 Buffer 是 32 字节一项的数组，四个字段的位置是固定的：Type 占的是第 0 个字，Size 占的是第 1 个字，Address 占的是第 2 个字（加 0x10），Stride 占的是第 4 个字。gtx 的实测里，t1 给出的属性描述符里 Type=5、offset 落在 0x400 与 0x410，印证的是 pan 源码里 1024 的基，pan 指 Mesa 的 Panfrost/Panthor 家族驱动。t3 给出 NEAREST 加 CLAMP 的采样器默认形态。t4 的首描述符则点出了纹理的 Size 与批池地址。咱们要跟的链从表号一直连到像素，走的就是同一条路。

## 执行器实现：描述符链驱动的采样光栅

### 从描述符链提取，到光栅化提交

咱们把执行器写在了 rk3588-lite.c 里（[notes/102](../../notes/102-2026-09-06-panthor-m2n-quad-sampler.md)），它走的是认形态的路子，并不逐条地解释指令。RUN_IDVS 时刻从真描述符链提取：SRT 的 t4 表项指向纹理描述符，纹理则指向下一级的 Surfaces 与 Plane，顶点则从 t2 的 Buffer 数组里解。光栅化（把顶点围出的 quad 铺成一块块像素）放在 RUN_FRAGMENT 的时刻做，NDC（归一化设备坐标）做轴对齐的映射，NEAREST 的采样，按目标的缓冲布局编号提交（笔记里的 bf，bf=2 指的是线性，bf=12/13 指的是 AFBC 家族）。提取全由 guest 的描述符数据驱动，没有一个像素是硬编码的，这是研究线从头到尾的纪律。

顶点的解析是件脏活。t2 的 Buffer 里至少有四种形态：16 字节交错的、8 字节分离的、uv 与 pos 换序的、32 字节步长交错的，咱们把形态逐个试了过去，由 quad_sane 挑出合理的那组。第 4 种形态解开了之后，mutter 的 novert 类（顶点缓冲里只有位置、uv 由 VS 从常量算出的那类，规模约 570 个 draw）也全部落了网，326 个 pending 对上了 326 个 raster，弃权的倒是零个。

受控面咱们铺到了 9/9（[notes/102](../../notes/102-2026-09-06-panthor-m2n-quad-sampler.md)），纹理的档位从 2×2 一路到 256×256，子区域的采样从 0.25 到 0.75，常量色与 clear 的回归也都在。它后来在 panic 排查的轮次里长到了 11/11，日常回归跑的是 7 项的子集：

| 受控面 | 结果 |
|---|---|
| 纹理 2 到 256 的全屏档 | 全部 PASS |
| 子区域 quad（0.25 到 0.75） | 全部 PASS |
| 常量色与 clear 的回归 | 全过 |

还有两处细节也值得咱们记（[notes/102](../../notes/102-2026-09-06-panthor-m2n-quad-sampler.md)）。Mesa 会把 glClear 并进 draw job 的 FBD（帧缓冲描述符，合并的记号是渲染目标 RT 的 bit31 置位），咱们让 staging（CPU 写像素、GPU 再搬运的暂存缓冲）提前铺上 clear word，quad 外的区域就是 clear 色而非残内存，受控测试早前靠新鲜页面侥幸混过的隐患也一并堵上了。模型的边界是执行器只认 NEAREST、轴对齐 quad 与 RGBA8，AFBC 在模型里是自洽布局的近似，并非原样的压缩编码。这两句话在后面的每一轮宣称里都有效。

### mutter 的渲染种群与三个翻案

受控矩阵 9/9 PASS 的路上，咱们翻了三个案（[notes/102](../../notes/102-2026-09-06-panthor-m2n-quad-sampler.md)）。bf=13 的缓冲旧标签写的是 AFRC（Arm 的帧率压缩格式），翻案后确认是 AFBC Tiled：模拟机广播的 TEXTURE_FEATURES 能力位根本没开 AFRC，所以 Mesa 压根不会选它。纹理的 payload 曾整体错乱，根因是纹理读的三形态判别少了线性分支：Mesa 上载纹理用的 staging 缓冲被按平铺布局读，压缩 body 整个写进了被置换过的纹理。还有一处 640×480 屏上冒出的 701 像素文字行，当时的来源存疑，两轮之后咱们确认它是内核 simpledrm 早期启动控制台的残留：rockchipdrm 没接管显示的轮次里，它压根不是 GPU 的输出。

再看 mutter 的渲染种群普查（[notes/102](../../notes/102-2026-09-06-panthor-m2n-quad-sampler.md)），桌面的 draw 分成了三类。字形走 512×512 的 bf=13 图集，一次开机的量约 430 个 draw。壁纸走的是 3840×2160 纹理下采样到 1920×1080，再合成进 1024×600 的主缓冲。主合成则是 bf=12 的整屏搬运。咱们把三类的数据路径都测绘清楚了，执行器的覆盖面也随之清楚：常量色类、采样类、blit 类各有各的路，VS 语义的 draw 超出固定功能采样器的射程，这个边界留在了明处。

### 合成链打通，panic 露头

咱们在 [notes/103](../../notes/103-2026-09-07-panthor-m2n-mutter-composite.md) 里把合成链的最后一环接上了，壁纸链的全图当时测绘成了这样：

```text
CPU 壁纸像素 → staging（线性）
  → GPU blit 上载 → 3840×2160 bf13 纹理（raster 写，8.3M px）
  → mutter 下采样 draw → 1920×1080 bf13（raster 写）
  → 主合成 blit（RUN_FRAGMENT only）→ 1024×600 bf12（try_blit 写）
  → VOP scanout：扫描源与主 FBO 的物理地址精确一致
```

把链打通靠的是两笔关键修。一笔是 raster 的 LRU（8 槽的设备态缓存）：合成 blit 的源是长命的 plane 描述符，不在批池的邻近窗口里，咱们改成由写方登记、blit 回退查。另一笔是写路径的严格翻译：宽松版翻译跨 VM 的别名会给错页，写的路径从此只走绑定地址空间的严格版。接上了之后，CPU 的壁纸像素进 staging，GPU blit 把像素上载成 3840×2160 的纹理，mutter 再把它下采样到了 1920×1080，主合成的 blit 则落进 1024×600，VOP 的扫描源与主 FBO 基址精确一致。链路通了，新的敌人也登场了：采样全开的轮次里，guest 内核在会话启动段约 130 秒处会概率性地 panic。当时咱们的头号假说是负载本身：BQL（QEMU 的全局大锁）下单线程光栅化 830 万像素要跑数秒，电脑侧的 watchdog NMI 会判死。异步分片（128 行一片、片间让锁）随之落地。负载假说下一幕就被证伪了，为验证它而引入的异步分片，一度被判定成了毒本身，真根因却要等到幕五的散射才浮出水面。

## 腐蚀追凶：一腐蚀，三受害者

### 失败矩阵，一路杀假说

panic 的排查，咱们用 7 轮启动矩阵开了场（[notes/104](../../notes/104-2026-09-07-panthor-m2n-panic-archaeology.md)）。崩点恒在会话启动段的 127 到 152 秒。同步的崩，异步的也崩，像素上限的有无改变不了它，body 数学的收紧与否同样改变不了。

| 轮 | 光栅形态 | 像素上限 | 结果 |
|---|---|---|---|
| 1 | 同步 | ≤1920×1080 | 330s 稳定（当时以为定论） |
| 2/3 | 同步 | 无 | ~128-130s 崩（DABT 数据访问异常中断与 NULL 两种形态） |
| 4 | 异步 BH（下半部） | 无 | ~128s 崩 |
| 5 | 异步 BH | 有 | 240s 稳定（运气好） |
| 6 | 异步 BH | 有，tiled 收紧 | ~143s 崩 |
| 7 | 异步 BH | 有，回滚线性 | ~150s 崩 |

watchdog 判死论与 body 越界论在这里双双证伪了。咱们把三轮追加判别做成了剥洋葱。NOWRITE 轮把采样、配对、hold 全跑了，只有提交的写跳过，结果稳定过了会话启动段的 827 个 job，写有罪的判定就此定谳。completion 挂起对齐 fence 的机制跑通了，堵的是 UAF 竞态论，崩溃倒是照旧，UAF 的论证伪了。地址空间歧义论也试了，把全 AS 一致性写翻译加了上去，歧义的检查一次都没触发，这个论点也一并划掉了。逻辑排除到了最后，嫌疑收敛到光栅化 job 的提交写，而写日志级的取证显示每一笔都在界内，矛盾就这么悬在了半空。

同一轮深挖还带出了用户态的镜像现场：gnome-shell 也在此段崩过一回，崩点落在了 background.js:488，JS 的栈只有两帧，说明它死在了 native 深处。咱们把 core 陷阱（core_pattern 与 ulimit 都武装进镜像）也布置下了，只是 shell 受害的轮次才落得了 core。PID 1 受害的轮次永远无 core 可捡，force_sig 的路径直接跳过了转储。想抓 shell 的 core，咱们得多 boot 重试，等 shell 受害的轮次出现就行了。core 的捡法也不用走串口，电脑上的 debugfs 直读 rootfs.ext4 就能把它抠出来（[notes/105](../../notes/105-2026-09-07-panthor-m2n-one-corruption-three-victims.md)）。

崩溃率咱们也老实记过：10 轮里崩了 6 轮活了 4 轮，纯概率的分布，咱们不再宣称任何稳定配置等于写安全（[notes/104](../../notes/104-2026-09-07-panthor-m2n-panic-archaeology.md)）。窗宽的取证顺带排掉了 job 超时论：光栅化 job 的常态窗宽 6ms，最大的 377ms 正是壁纸上传本身，离 5 秒的 JOB_TIMEOUT_MS 有两个数量级。崩溃轮的日志尾巴咱们也翻过，最后的写全是合法的，misparse 的假设在证据面前退场。

### 三受害者并案

更吓人的现场把悬案打破了，[notes/105](../../notes/105-2026-09-07-panthor-m2n-one-corruption-three-victims.md) 里 PID 1 的 systemd 自己收到了 SIGSEGV，内核跟着打出了整台模拟机的 panic。咱们把原文引出来：

```text
Kernel panic - not syncing: Attempted to kill init! exitcode=0x8b (=139=SIGSEGV)
CPU: 1 UID: 0 PID: 1 Comm: systemd
```

咱们把三个现场并案看，图景就统一了：

| 受害者 | 崩溃形态 |
|---|---|
| systemd（PID 1） | SIGSEGV → kill init → 整台模拟机 panic |
| gnome-shell | background.js:488 SEGV → 会话解体 |
| 内核结构体 | 垃圾指针解引用 → watchdog lockup |

同一腐蚀的三个受害者，咱们看到的规律是谁碰到了毒页谁死。受害者的随机性恰好解释了崩溃签名的多样性，此前每种形态都被当成了独立线索追过一轮。机制的推论也顺：毒页多半是多进程共享的 file-backed 页（page cache 里的 libc 与代码页），哪个进程碰到了就死。PID 1 受害的轮次连 core 都留不下，force_sig 的路径直接跳过了转储。

### 真值表出手，两病分流

腐蚀的量级是 panthor 的 gems debugfs 给的，证据咱们引在 [notes/105](../../notes/105-2026-09-07-panthor-m2n-one-corruption-three-victims.md)。gems 的真值躺在 /sys/kernel/debug/dri/1/gems 下，是 per-BO（每个缓冲对象）的真值表，越界的审计从此有了权威的数字：

| BO | gems 实测大小 | 咱们的写 |
|---|---|---|
| 512² 图集 Render target | 1073152 字节 | 旧线性写越界 106KB（区间 0x20000 到 0x120200） |
| 壁纸纹理（11 级 mip 链） | 47149056 字节（45MB，L0 裸数据 33MB） | 紧式 L0 写 33.7MB，界内 |

图集的越界就此定下来，紧式的 body_base（4K 对齐头区）也随之上了。2GB 的崩溃转储咱们逐页核对过，崩溃轮的全部写手审计下来全在界内，可崩溃倒是没停：要么还有下一个越界者，要么病根本就不在越界。

同一天咱们还遇到了一个把两种病分流开的发现。NOWRITE 轮里的 shell 也死过一次，死于 SIGABRT：gjs function.cpp:1014 的断言 1==2，ubuntu-dock 扩展的兼容破绽，与 GPU 的模型无关。把 ubuntu-dock 在镜像里改名禁用了之后，NOWRITE 轮的 gnome-shell 全程活了。病其实有两种：一种是功能性的 gjs 断言，另一种是真的腐蚀，混在一起的时候谁都别想看清谁。

### SYNC 判别，显示点亮，壁纸作业二分

咱们用 [notes/106](../../notes/106-2026-09-08-panthor-m2n-sync-mode-and-greeter-wedge.md) 的判别矩阵把毒又收窄了一圈。FSQUAD 是采样 quad 执行器的总开关，表里的四行就是它的不同档位：

| 模式 | 写 | 延迟 | 结果 |
|---|---|---|---|
| FSQUAD=0 | 无 | 无 | 稳（5min+，shell 活着） |
| NOWRITE | 无 | 微 | 稳 |
| SYNC+紧式 | 有（内联跑完） | 零 | 稳（561 job） |
| 异步+紧式 | 有（BH 分片） | 毫秒级 | 崩（~326 job） |

咱们拿着同样的地址、同样的内容、同样的量做对照，内联的同步就稳，异步的就崩了，当时的判定写的是毒在异步机制本身。这是当时照证据记下的阶段性判定，真根因要等幕五的散射才浮出，但 SYNC 形态从此成了咱们的稳定工作姿势，后面的冲刺靠的全是它。

显示侧的突破也在同一晚。greeter（GDM 的登录界面会话）的僵局，咱们剥到了 logind 会话激活缺位：c1 会话的 Active 一直是 NO，咱们手动 activate 再踢了一把壳，新 greeter 就走到了 Registering display with GDM，DSI-1 也 enabled 了，VOP 的 scanout 真正接管了，1024×600 的模式起来了。会话激活缺位的最可能机制是 console=hvc0 下 VT1 从未成为前台，修复方向定为镜像内加 vt1-nudge 的服务，这一项到收官仍列在余项的清单里。

咱们对僵局的解剖当时就做了两层：KMS 线程在 ppoll 里等 card0 的事件，姿势倒是正常的。主线程 6 秒的窗口里零系统调用，卡死在了 futex，也就是 JS 与 GLIB 的层面（[notes/106](../../notes/106-2026-09-08-panthor-m2n-sync-mode-and-greeter-wedge.md)）。DBus 全超时只是主循环卡死的下游，会话激活缺位是当时最顺的上游候选，实验的现象与它兼容，不过还不够充分，得等 bootargs 修正后的 fresh 轮验证。

壁纸作业的二分是本幕最后一刀：咱们把大于 4M 像素的 draw 拒了，441 job 稳定了下来。第一版阈值写的是 8M，也就是 1024 进制的 8388608、十进制的 8.39M，而 3840×2160 的 8.29M 像素恰好小于 8.39，从门缝里漏了过去。对照每一轮崩溃的最后大写都是 3840 的壁纸 job，作业级的因果成立。紧式 body 数学、45MB BO 的真值、头区曲线这三方的写算术审计全在界内，泄漏的机制未解，工程上咱们用壁纸门顶住，再用 solid 模式把内容做了出来：大图的稀疏采样取主色，只写 solid 的头，壁纸 job 从 377ms 降到了 2ms。屏还是黑的，不过拼图都到位了。

## 可见达成：第一帧真实渲染内容

咱们在 9 月 8 日等到了打破全黑的 screendump，记录收在了 [notes/107](../../notes/107-2026-09-08-panthor-m2n-visible-achieved.md)。1024×600 的非黑占到了 98.67%，主色报的是 00a0ff，恰好就是壁纸的颜色。达成现场的链路实证如下：

```text
壁纸 draw(tex=3840×2160) → solid 模式 窗宽=2ms
下采样 draw → 真光栅 77ms → 1920×1080 的 solid 头
屏合成 → 1024×600 bf=12 输出
VOP scanout(mst=26f000→6456a000) → AFBC solid 解码 → 蓝像素
screendump：98.67% 非黑，主色 00a0ff
```

块里的符号咱们交代一下：mst 是 VOP 侧扫描缓冲的标识，箭头右边的 6456a000 是从它翻出来的物理地址。A/B 咱们也做了，固定蓝的 solid 模式 shell 存活零崩，采样色模式的 shell 在 24 秒 SEGV（单 boot 样本，当时记了 mesa 解析路径的嫌疑）。当年的复现命令就是一行环境变量加 resboot，写出来是下面的样子：

```sh
GPUDBG=1 FSQUAD=1 FSQUAD_SOLIDBLUE=1 GDM=1 \
  setsid nohup python3 sim/resboot.py 7200 > sim/logs/resboot.out 2>&1 &
```

随后的几个终段，咱们把成果推向了全屏：bf=2 线性目标改成逐块直写，1920×1080 的下采样全光栅跑通，双缓冲的翻页与合成落点精确一致，空 layer 回退把背景带进了合成。screendump 一度打出了 100.00% 的非黑、主色 d0032b 的全屏，机器存活了 7 分钟。三张证据 PPM（visible-desktop、real-desktop、fullscreen-desktop）入了库，其中真图版是 4.71% 非黑的瞬态，独立色数十种且全部与缓冲里的真壁纸色同源。

M2n-visible 的判定达成，按的正是开场立下的证据门（[notes/107](../../notes/107-2026-09-08-panthor-m2n-visible-achieved.md) §7）：真实图像内容经完整的 GPU 数据路径上了屏，可靠纯色与瞬态真图两种形态都留了档。判定词咱们没敢多用，因为瞬态真图的 boot 间方差还摆在那里，双缓冲的翻页会在内容页与空页之间交替，稳定的复现要到幕五的缝合修完才拿到。

咱们在同一天把真图模式的迟发毒档案建了起来（[notes/107](../../notes/107-2026-09-08-panthor-m2n-visible-achieved.md)）：一轮 414 秒的内核 paging fault，伪指针的值 00472665ff47268d 恰好是真实壁纸的颜色，腐蚀的晚窗口（4 到 7 分钟）终会命中 shell 或内核，而固定蓝的模式能稳过 5 分钟。受控的回归 7/7 也全过，字形位姿的难题同时定了界：novert 顶点里的 r8 是 0xfffd4240，它是页选复合的编码而非裸指针，解它的办法是给 FAU（快速 uniform 常量区）建 RAM 模型，这就成了后面独立的一役。

到这里咱们可以回头再看当初的人月级判决了。“覆盖 GNOME 是 9–24+ 人月级高风险研发”，这个判定被实证推翻（[notes/107](../../notes/107-2026-09-08-panthor-m2n-visible-achieved.md) 的原话），推翻它的方式却值得说清。咱们写的并非全量指令解释器，执行器靠的是受控矩阵加固定功能近似，模型的边界一条条写明：solid 纯色壁纸类走通，采样几何是 fallback 的全屏 quad 近似。判决估的人月数针对的是完整执行器，而桌面可见这件事，固定功能的近似就够得着。深水区是真的深，但浅滩也是真的能蹚过去。

## 散射根修：485677 次错页写

### 迟发毒的根因

真图模式跑起来了之后，迟发毒（4 到 7 分钟窗口内的崩溃）成了残局之首。咱们在 9 月 10 日把根因定了下来（[notes/108](../../notes/108-2026-09-10-panthor-m2n-poison-root-cause.md)）：GPU 的 BO 在 VA（虚拟地址）空间里连续，物理页却是散射映射的，而光栅化按 base 加线性偏移写，跨过了断裂页之后，写就落到了无关内存。战役五做 VOP 仿真的时候，代码里早就写着 bo 的 iova 映射不保证物理连续，所以 VOP 的扫描是逐页缝合的。光栅化的路径从头到尾没应用同一条常识，毒就藏在这里了。

探测器的数字把咱们吓了一跳：scatter 计数出了 485677 个错页，折合 457 个 job、约 1.9GB 的错向写。这个根因一次解释了此前所有悬案。崩溃的概率性，取决于分配拓扑把断裂点落在 span（一笔写覆盖的区间，08 章界定过）内的什么位置。壁纸的 job 最毒，因为它的 span 最大。界内的审计全过，因为审计按的是 VA 算界，写却按错误的物理地址落地。固定蓝的模式较稳，因为纯色的头写得少。错向的写还常常打中 GPU 的页表页，后续的翻译跟着错，级联也就放大了。根修是全部写路径逐页缝合：光栅化主路径、blit 的头与 body、clear 的铺写、整帧镜像，一律都改走逐页的翻译。修完了之后，真图加 GDM 机稳到了 340 秒以上，受控的回归 7/7 全过，真图屏出了 553 个独立色，当时的历史最高（[m2n-stitched-realimage.ppm](../../../sim/logs/m2n-stitched-realimage.ppm)）。

### 读侧的病，与 staging 即真相

写侧缝合了之后，读侧的同类病开始显形（[notes/109](../../notes/109-2026-09-11-panthor-m2n-screen-garbage-root-cause.md)）。用户对着截图问了一句你确定嘛，把竖条纹垃圾送回了解剖台，双 bug 就此分清了。一个是背景回退的单维门，它把 1027×35 的 damage 条带（合成器里报告的重绘区域）当成了背景 actor，拉伸到了满屏。另一个是纹理读不校验 body 的偏移：垃圾头其实是 GPU 页表页的 PTE，被截 32 位当成了小偏移，页表页就这么被当像素读出了自画像。屏上高频复现的 007b61，正是 PTE 高位的物理地址域。双修之后 253 个独立色的结构化内容上了屏，MCP（咱们外接的读图模型）的复判说结构化图像非噪声。读侧散射是同一个根因的另一种表现（[notes/110](../../notes/110-2026-09-11-panthor-m2n-true-wallpaper-fullscreen.md)）：按线性物理地址加偏移的读法读大缓冲，跨了断页同样读错页，表现是内容的前缀有效、断页后全零，全 VA 逐页缝合随之铺到了 9 个调用点。

咱们从 [notes/109](../../notes/109-2026-09-11-panthor-m2n-screen-garbage-root-cause.md) 里记下一条验收的方法：直方图证明的只是颜色而非布局，像素的行程分析（游程加周期检测）才能区分图像与元数据，同低字节变高字节的游程就是指针，递增的小字段就是偏移。MCP 读图在那一轮立了功，不过它的身份到了幕六还会再变一次。

[notes/110](../../notes/110-2026-09-11-panthor-m2n-true-wallpaper-fullscreen.md) 的关键机制发现把内容质量推了上去：壁纸链的每一级转写都在损失细节，唯一保有全分辨率真像素的，是 CPU 上 glTexImage2D 时的 staging。识别特征是线性布局的大纹理（≥1024×768）。咱们沿细节损失链做了五连修：

| 环节 | 损失 | 修法 |
|---|---|---|
| VOP 的 AFBC 判定门 | 结构字节被当像素显示 | 扫首行前 4 头，全过校验才按 AFBC 解 |
| 背景注册的布局编号 | bf=2 缓冲被按 U-tile 读 | 布局号随缓冲走，bf=2 归线性 |
| 背景择优 | 近全黑的整帧挤掉好图 | 8 点命中数择优，后来者须更优 |
| 细节源头 | 中间链全是转写 | 线性大纹理直接注册为背景源 |
| 读侧散射 | 断页后读成别人的页 | 逐页缝合铺满全部读调用点 |

咱们单槽的缝合缓存还藏着跨 job 的陈旧状态，新进程意味着新的 VM 与地址空间，陈旧的翻译就是受控 8×8 偶发 FAIL 的真身，job 的提取入口重置缓存之后，8×8 连跑三轮也全过了（[notes/110](../../notes/110-2026-09-11-panthor-m2n-true-wallpaper-fullscreen.md)）。

毒根修完了之后，咱们连带宽的妥协也解除了：BGFULLRES 让 3840×2160 走了全采样，窗宽落在了 358 到 1230ms，还在 5 秒的超时内，中间链的保真从此有了源头（[notes/110](../../notes/110-2026-09-11-panthor-m2n-true-wallpaper-fullscreen.md)）。咱们修完的形态是 99.99% 全屏、930 个独立色，MCP 清晰辨认出了白色熊猫图案、放射光效与平滑紫渐变，两次 boot 复现了 922/930 色，证据 [m2n-true-wallpaper.ppm](../../../sim/logs/m2n-true-wallpaper.ppm) 也入了库。这一幕收官的时候人人都满意，而幕六会证明，满意的证据链里埋着两个没被察觉的雷：参照图是错的，读图的 MCP 也会幻觉。

## 校验纪律收官：MCP 幻觉、参照错案与数值判决

### 用户的眼睛，和五点标记

用户的复检一路都在当裁判。第一轮的原话是熊猫露出来的是 1/4，而且位块（blit 搬运的那些位图块）错位，咱们在 [notes/111](../../notes/111-2026-09-11-panthor-m2n-display-takeover-and-staging-puzzle.md) 以此开局，建了确定性显示接管基建：帧节拍重绘、屏级快照、地址空间捕获、标记取证。五点纯色标记注入是坐标取证的标准仪器，注入了 ff0000、00ff00、0000ff、ffff00、00ffff 五个色点，笔记里给出坐标的三个点位也都精确落了位：

```text
注入点(节选三处)     落位结果
(8,8)               精确命中
(512,300)           精确命中
(8,591)             精确命中
```

写入到显示的坐标链路分毫不差，咱们由此知道错位不在坐标的层面，问题出在内容来源的层面。staging 碎片的悬案移交时，当时的假说是 GNOME 渐进上传。

### MCP 读图的幻觉

次日的复检原话是“我不接受半成品”，咱们沿读路径做了五连实验（[notes/112](../../notes/112-2026-09-12-panthor-m2n-staging-read-path-experiments.md)），一度宣称背景到了像素级吻合（差 5-9），浣熊脸也有了局部成形（差 54-66）。实验矩阵里跑赢的形态是 stage 数组加 owner-AS 缝合加盒式滤波：

| 读法 | 结果 |
|---|---|
| AS 锁定（单点捕获） | 部分改善，光芒连贯，脸仍碎 |
| PA 线性全量（注册期基址） | 10 万色噪声（越过连续前缀就是散页） |
| 混合（前缀线性加越界缝合） | 更糊（步长 2 加接缝） |
| stage 数组加 owner-AS 缝合加盒滤 | 最优：背景差 5-9，脸区差 54-66 |

当晚的深夜追加把这一切推翻了，咱们拿数值复核了每一个宣称：staging 裁剪 dump 的数值差 94，却被 MCP 两次描述成了完美浣熊，圆眼三角鼻的描述连边缘都清晰，数值的复核却全错。此前脸局部成形的进度宣称，建立的主要就是这个幻觉。写下来的教训只有一句，MCP 的读图判定必须数值复核，而它直接催生了下一件武器。

### verify_screen：验收武器化

用户定调 MCP 的方式太粗糙、有没有更好的办法，于是咱们把散装了 6 遍的取证脚本固化成了 [verify_screen.py](../../../sim/verify_screen.py)（[notes/113](../../notes/113-2026-09-12-panthor-m2n-verification-weaponized.md)）。工具是纯标准库写的，下面是它的三种模式：

| 模式 | 用法 | 判据 |
|---|---|---|
| 全屏对照 | 屏 PPM 对参照 PNG | 背景域 p90≤20 且结构域 p50≤40 判 PASS |
| 1:1 条带 | --strips 按行对照 | 原位差加限界位移搜索，逐行判定 |
| 原始页分类 | --classify 吃二进制 dump | 按熵与指针特征给 4KB 页分类 |

p90 与 p50 是分位数的口径，背景域九成的块差要落在 20 以内，结构域一半的块差要落在 40 以内，咱们就把线画在了这里。

咱们把判定固化成了固定的姿势，每轮 boot 跑的都是三条命令：

```sh
# 全屏对照（每 boot 必跑）
python3 sim/verify_screen.py sim/logs/X.ppm --ref .../warty-final-ubuntu.png
# staging 的 1:1 条带对照
python3 sim/verify_screen.py sim/logs/strips.ppm --ref .../warty-final-ubuntu.png --strips
# 原始字节 dump 的离线分类
python3 sim/verify_screen.py sim/logs/face.bin --classify
```

咱们把工具文档字符串里的一句原文引出来：“判定只看数字，MCP/人眼仅复核热图。”

判决从 MCP 的自由心证换成了确定性数值，MCP 降级成了热图旁白，判据的位子永远不再给它。工具首跑就给咱们翻了两件案：平铺快照其实更糟（背景 p90 高到了 92），此前的背景吻合是角落采样的幸存者偏差。参照后来写死成了 warty-final-ubuntu.png，理由咱们放在下一案讲。

### 参照错案：判据自己错了

武器到了手，最大的案子反而出在判据身上（[notes/114](../../notes/114-2026-09-12-panthor-m2n-wrong-reference-and-snapshot-voting.md)）。greeter 实际显示的壁纸是 warty-final-ubuntu.png，它是 rootfs 构建日就写进镜像的 Ubuntu 默认壁纸，而 [notes/110](../../notes/110-2026-09-11-panthor-m2n-true-wallpaper-fullscreen.md) 到 [notes/113](../../notes/113-2026-09-12-panthor-m2n-verification-weaponized.md) 一路拿来当判据的，拿的却是 cnusr25-Simple_Raccoon_Dark.png。两张同为暗紫的色系，背景块的差落在 22 到 25 之间，够接近了，却永远过不了线。脸区与 8 个壁纸变体的全读法对照，结果自然全不匹配。决定性的证据来自 span dump：staging 的内容与 warty 的原位字节精确一致，逐字节的 mad（平均绝对差）是 0.00，delta 同样归了零。想复现的读者从解开的 rootfs 里取参照，镜像内的位置是 /usr/share/backgrounds/ 目录，文件名就是本章一直写的 warty-final-ubuntu.png，Ubuntu 的壁纸包里也有同一张。连环翻案的清单咱们记在下面：

- 背景像素级吻合 5-9：两张壁纸都是暗紫底，色差被当成了吻合
- greeter 调光恒偏 -10：其实不存在，换对参照后色偏归零
- 脸区与全部变体不匹配：测的 8 个变体里根本没有 warty
- MCP 的完美浣熊：幻觉乘以错误参照的双重污染

快照链的两处修复也在这一案里。注册路径的 last-wins 让回收残页顶掉好快照，咱们改成三门一致投票（注册不清位、严格更优才换、权威采用同样投票），残页的样本就被挡下了。快照读路径从线性物理地址改走了 owner-AS 的逐页缝合。修复后的结构域 p50=25.2 首次过线，色偏归了零，剩背景 p90=33.7 的顶带损伤。

顶带的损伤还有一段弯路值得记（[notes/114](../../notes/114-2026-09-12-panthor-m2n-wrong-reference-and-snapshot-voting.md) §5）。方差峰的联合搜索一度给出过漂亮的结果：全部的结构行都在 dx=-256 恒定命中，y 的拟合系数是 0.99，置换其实就是纯平移，行的移动是 272，列的移动是 256，折合的字节偏移是 +0x3FC400。span 的行识别接着把 staging 切成了三段：行 0 到 272 与 warty 的原位逐字节精确，行 273 到 546 是 warty 里不存在的精确灰度带，行 546 以下则是平移的副本。顶点解析做过一阵头号的嫌疑人，GPUVERTDUMP 的取证把它放了：打印出来的四个字其实是背景回退 quad 的顶点 0，回退本身是满幅恒等的，光栅化的平移无从谈起。真正的交叠落在了写侧。取证 dump 里被追踪的两个区域，reg2 的渲染目标 PA 0x58e00000 正好落在 reg1 staging 的区间里，也就是从 0x57800000 往上的 22MB，咱们的光栅化 job 对它写了 135 个 sbrow（超块行），而 reg2 自己的 staging 也在这个写入区间里，全 boot 的 scatter 偏离高达 69767 次。mutter 的 BO 是世代链：staging₁ 释放了，页回收成 job₂ 的渲染目标与 staging₂，与咱们光栅化 job 的写区间在物理页上交叠。交叠若真是 mutter 的页复用，它就是无害的自然形态。若是咱们写翻译错页，那就是咱们在腐蚀 mutter 的 staging₂。咱们到收官也没能把这场核对跑起来，交叠就按页复用的自然形态处理了，残留的方差记在幕末的清单里。顶带损伤的真身是另一对写者，咱们到下一小节再给答案。

### 顶点形态 E，与双写者的互踩

顶带损伤的破案横跨两件笔记，咱们跟着证据走完了全程。顶点格式破译补上了第 5 形态（[notes/115](../../notes/115-2026-09-12-panthor-m2n-vertex-form-E-and-composite-stage.md)）：32 字节步长的缩放空间与像素空间两种顶点，背景回退的满幅假设从主力降成了每次开机 1 次。真正的根修在扫描输出的布局上（[notes/116](../../notes/116-2026-09-12-panthor-m2n-wallpaper-visible-achieved.md)）：复合 job 对扫描输出实测是 bf=12 的线性头，而咱们的镜像重铺写与 VOP 解码一直用 bf=13 的平铺头。两边是各自自洽的，底部 92% 都是对的，但两种 body 的寻址差了 0x800，mutter 复合的 2.4MB body 整片覆写了咱们的 body 区，受损区正是 greeter 顶带的 damage 条带。写读同切线性之后过了数值线。用户复检又抓出了底部的黑横条加绿斑，原因在 600÷16=37.5 的整除截断：整除的截断让第 38 排 tile 从未被铺，咱们补写了半尾 tile（越界行钳制到 591），黑绿都归了零。

## 全卷收官：三条带走的方法论

一条是命令流解剖的办法。闭源其实不等于黑箱（NPU 章说过同一句话）：边界两侧总有开放的材料，Mesa 的 v10.xml 与 ISA 指令表、panthor 的源码、gems 与 gpuvas 的 debugfs 真值，咱们拿 dump 实测驱动理解，没有一个像素是硬编码的。NPU 章咱们拿这套办法做到了逐字节一致，GPU 研究线拿它做到了固定功能采样光栅，两条线用的是同一个办法，让 guest 的真数据当驱动力，咱们的代码只做解释。

一条是内存腐蚀的侦探法，咱们在这场战役里交的学费也最深。症状的受害者随机，不代表病的种类有多种，一腐蚀三受害者的并案做完之后，追查的方向才对。真值表（gems 的 per-BO 尺寸）帮了咱们的忙，越界嫌疑从此变成可计算的审计。判别实验的法子更狠，NOWRITE、SYNC、作业二分各砍了一刀，砍掉的都是一整类假说，与网络章 GMAC 冤案里 headless 轮杀显示家族的手法同宗。最贵的教训是，老代码里其实早就写着一条常识，iova 映射并不保证物理上的连续，可它换了一条路径就会失效。VOP 的路径照着它办了，光栅化的路径偏偏漏了，散射根修补上的正是漏掉的那一半。

收尾的一条是验收纪律，这也是咱们最想带走的。人眼会被似是而非的结构说服，MCP 的读图会幻觉，连判据自己也是会错的（参照错案就是），所以判据要数值化、参照要验明正身，机器判据加人眼终审的两段缺一不可。受控面守住的是已知，证据入了库等复核。NPU 章的假证据和这次的 MCP 幻觉，两回的病根是同一个，都是没上数值复核的毛病。

## 边界与余项：研究线没有做完的事

余项咱们按 [notes/116](../../notes/116-2026-09-12-panthor-m2n-wallpaper-visible-achieved.md) §5 归并，LINEAR 采样一条出自执行器立模型时的边界（[notes/102](../../notes/102-2026-09-06-panthor-m2n-quad-sampler.md) §4）：

- 显示形态是 REPAINT 接管：bg_screen 快照按 60fps 重铺，mutter 自身合成的输出仍是中间产物，复合 stage 曾实测 62.6% 黑，AFBC 纹理读侧的平铺参数仍未核对
- UI 层（greeter 时钟、输入框）、字形位姿与 vt1-nudge 服务：字形卡在 FAU（快速 uniform 常量区）的 RAM 模型上，r8 是页选复合编码而非裸指针，需要独立一役。vt1-nudge 是 console=hvc0 下把 VT1 推上前台的会话激活服务，幕三点到过它的修复方向
- LINEAR 采样、blend、旋转、多纹理，都在受控矩阵的边界外
- boot 间方差残留：staging 偶发卷绕与混合（回收页交叠），三门投票加单射探针（33 点互异 PA，别名 VM 会重复）已大幅收敛，未归零

更大的边界，咱们还是重申开场那句话：全部是 QEMU 的仿真取证，时钟、电源、DDR 时序这些硬件行为都不在证明的范围里。研究线的产出是理解材料，它反过来撑着 GPU 章的每一句话。反哺有个现成的例子：GPU 章的旁白讲过固件镜像里 64KB 的共享内存区，文件里只有 124 字节的初值，其余全是 MCU 上电后自己填的。假 MCU 每写一个字段的时候，咱们都得知道真固件会写什么，理解到的这些最后都落回了主线章节的每句断言里。板上主线仍然是验收的唯一依据。

全卷到这里就收官了。从 [平台章](00_platform.md) 那场无声的 bootloop 起，咱们从 U-Boot、内核、LCD、GPU 固件、rootfs、网络引擎、外设、NPU 一路讲到这里的仿真战役，这块板的主线与支线都讲完了。研究线的余项挂在 notes 与 sim 里。GPU 章说不展开的那半句，到本章补上了，咱们下一块板见。
