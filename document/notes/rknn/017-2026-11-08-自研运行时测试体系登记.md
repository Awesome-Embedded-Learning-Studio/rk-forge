## 出处与边界

- 测试目录 [README](../../../src/rknpu/rk3588/tests/README.md) 顶部有
  出处警示：这套 E2E 验证由 GPT 6.1 Sol 生成，「请适度采纳」。测试本体
  经过 009–016 各轮实板与主机复核反复打磨，但其生成出处如实记录在此。
- ASan/UBSan 统一 `detect_leaks=0`，不含泄漏检测。
- QEMU 只验证软件执行顺序与数据搬运，不执行 NPU 算术。
- 主机回归通过不代表实板验收，两者在证据目录上分层。

## 层次与入口

| 层 | 入口 | 内容 |
|---|---|---|
| 主机回归 | `run_host.py`（`--suite basic\|native\|media\|oracle\|all`） | 构建自研运行时后跑全套主机测试，每次运行独立目录，`verification.json` 记录逐项退出码 |
| 构建部署 | `build_board.py` / `deploy_board.py` | 只写 `out/`，不连板。生成 AArch64 bundle（`build-manifest.json` 记编译器与摘要），原子替换 NFS 文件，检查 ELF 架构、动态依赖与 shell 语法 |
| 板端执行 | `board/run.sh`、`verify_legacy_sync.sh`、`multicore/run.sh` | BusyBox 环境，无需 Python |
| 主机复核 | `verify_npu.py`、`verify_media.py`、`analyze_decode.py`、`analyze_sync.py` | 独立读取板端证据目录做严格判定，不依赖板端结论 |

## 测试清单

主机 pytest（`tests/host/`）：

| 文件 | 管什么 |
|---|---|
| `test_board_runner.py` | 模型/运行输出隔离，API 与写文件失败必须返回错误 |
| `test_boot_check.py` | 23 个驱动/IOMMU 绑定、PM 状态与错误日志（大写 `RKNPU` 精确匹配在 015 修正） |
| `test_replay.py` | 空证据、缺少提交、早期提交差异均拒绝 |
| `test_npu_evidence.py` | 缺失、全零、NaN、字节差异均拒绝 |
| `test_corepool.py` | 真实核心池 header、8000 次并发租用、probe/回收/错误路径，ASan/UBSan |
| `test_media_demo.py` | demo 正常/损坏/硬件错误三类输出，JPEG EBUSY 与 request-only SPS 的初始化顺序回归（复现 015 修掉的两颗雷） |
| `test_media_suite.py` | 正常、核心空闲、错误计数增加三种判定及 JPEG 内容判定 |
| `test_vendor_oracle.py` | 54 种提交序列、九模型首提交全部 GEM、三模型非零 CPU 缓冲区，默认不进 pytest，`RKNN_RUN_VENDOR_ORACLE=1` 显式启用 |

原生 C++（`tests/native/`，CTest 3/3）：`execution_test.cpp`（真实模型分段执行、CPU 搬运、多输出、错误传播）、`driver_test.cpp`（mmap 失败回收、上下文析构、fence 就绪/超时/错误）、`output_test.cpp`（真实板端快照、布局边界、负零、MEM_SYNC ABI）。

板端（`tests/board/`）：`board_harness.c`、`legacy_trace.c`、`multicore/` demo 源码与三个 shell 入口。`fixtures/` 是模拟 V4L2/legacy ioctl 的 C 测试替身，仅用于主机模拟。
