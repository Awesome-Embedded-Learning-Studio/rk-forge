> 一句话:NN_BG 是 FlatBuffers,指令模板原文就在模型里,librknnrt 的装配 = 模板拷贝 +

> 剩 FlatBuffers schema 细节(dsh-009)即可开写替代引擎。

## 2. task 表:561 行 = 三套核数方案(A/B/C)

| 段 | 行 | 数 | lane 分布 | 语义 | set_core_mask 实测 |
|---|---|---:|---|---|---|
| A | 0..245 | 246 | 0/1/2 各 82 | 3-lane 联动(默认/AUTO) | mask=0→246;mask=1→start0 数 82 |
| B | 246..382 | 137 | 0:71/1:66 | 2 核方案 | mask=3→start246 数 132(66×2) |
| C | 383..560 | 178 | 0:64/1:57/2:57 | 3 核非联动 | mask=7→start383 数 171(57×3) |

- 两次运行(AUTO vs mask=1)dump **逐字节全等** → 三套全是 init 预建,run 不改写
- 内核 rknpu_job.c 按 use_core_num 选 subcore_task 槽位:2 核用 [0]/[1],3 核用 [2..4]
  ——与 B/C 预备一一对应;B/C 尾部 op52/54 有 5+7 行特殊任务未被提交
- 行内恒定:flags=0、int_clear=0x1ffff;按 op 类型分三档:
  conv 族(546 行 amt=124/en=0x1d/im=0x300)、op53(5 行 106/0xd/0x300)、
  op52/54 尾部族(10 行 26/0x60/0xc00,只写 0x6/0x7xxx bank)
- op_idx 1..54(NNBG 内部算子;JSON 里 nodes=1 单 NNBG 节点,const_tensor=0)
- 尺寸来源:dsh-008 §2.1(task_bytes=40×561、regcmd=Σ 槽宽,与实测严丝合缝)

## 3. regcmd 指令流:8B 包 + 槽 + trailer

```
包 = u16 reg | u32 value(偏移+2,非对齐) | u16 tag
tag = ((reg>>12) < 8) ? (1 << (bank+8)) | 1 : …   ← FUN_001a20e0 编码公式
```
- 三方闭环:本仓 dump + phhusson instrs.h + TRM(mtx512 npu_hw.h)/内核
- **chunk 槽 = align(amt,16) 包**(=源槽 (amt+11)&~7):124→128/26→32/106→112 包,
  561 槽总长 566144=regcmd 缓冲尺寸,步长法则 560/560 全中
- **槽尾 4 包 PC trailer(我们此前漏读 amt×8 之后的 0x20)**:
  `0x0010`=PC_BASE_ADDRESS→下一 chunk IOVA(lane 末=0 链终止)、
  `0x0014`=PC_REGISTER_AMOUNTS(0x3f;B 段带 0x1000_0000、C 段 0x2000_0000 模式位;
  内核 SUBMIT 时还会用 (amt+4+scale-1)/scale-1 覆写)、
  `0x0000` tag0x0041 常量包、`0x0008`=PC_OPERATION_ENABLE←enable_mask
- 寄存器词汇表 150 个:bank0=PC、1=CNA、3=CORE、4=DPU、5/6/7=待命名;
  chunk 头 4 包固定 S_POINTER←0xe(与内核 rknpu_job.c:308 同源)
- lane 位只进 0x1004(CNA_S_POINTER)+0x3004(CORE_S_POINTER):value |= lane<<28

## 4. NN_BG 容器文法(Q2 纠错)

- **0x70 起的"u16 寄存器表"是 FlatBuffers vtable**(vtable_len=0x2c/obj 0x54/20 slot),
  根表 0xa4;字段抽查全中:f1→"RKNPU v2"、f7→"1.5.0+1fa95b5c(compi…"、
  f16→"static_shape"、f19 表含 {0x6d0e40, 0x341000}(=gem1 模板池起点+internal 尺寸)
- **指令模板原文在模型里**:op1 tile0 @model 0x6bfb0(NNBG 内 0x6bf40),
  每条 8B `{u16 rsvd; u16 reg; u32 value}`(注意与 regcmd 包差一个 tag 编码)
- gem1 = [权重 0..0x6d0e3f][模板池 0x6d0e40..0x731abf][尾 0x100];
  **regcfg_off = 模板池包下标**(=字节偏移/8):首行 0xda1c8×8=0x6d0e40、
  末行 0xe6358×8=0x731ac0,池内 395 个槽被 561 行复用
- 模板→运行包的差异实测(128 包槽仅 12 处):2 lane 位 + 6 值回填 +
  4 trailer;值回填位点:0x104c(0xb→1)、0x1070/0x1110/0x4020/0x5020(模型 0→IOVA)、
  0x1180(0→0xfff)——**地址槽在模型里是符号 0,加载期回填**

## 5. builder 代码地图(静态侧,dsh-008)

```
FUN_00307a30(v2 init)
├─ FUN_004b1250  尺寸公式+分配 regcmd(executor+0x1e0,flags 2/4)/task(+0x1f0,2/0xa)
│                + 8 趟循环(A×3=mode1, B×2=mode2, C×3=mode3;edge 六向量
│                +0xa0/+0xb8/+0xd0/+0xe8/+0x100/+0x118,仅 +0xa0 组尺寸×3)
│   └─ FUN_004adf40 ★装配器:逐包拷模板(FUN_001a20e0 编码)+写 40B task 行
│       ├─ FUN_002f1190  lane patch(value+=lane<<28,回写源)
│       └─ FUN_002f9fc8  按 reg_list 裁剪包范围
├─ FUN_002f1fc0  ★≠regcmd 搬运(dsh-005 标错)=RKNNTensor 反序列化/链接
└─ FUN_004b2520  调度元数据两张 map + 二次地址重定位(FUN_002f8200:扫 regcmd,
                 value 低16==tensor id 的包→IOVA)+ DMA cache flush
```
- 每 op chunk 数 = Σ_edges(nsub+1),nsub=ceil(words/((1<<max_task_shift)-1));
  算术核验:A 段 82-54=28=Σnsub ✓
- enable_mask/int_mask 来自模型反序列化的 task 描述对象(+0x9c/+0xa0),非硬编码

## 6. 对前序结论的更正账(累计)

1. dsh-005 §8.2 `task_obj_addr` **不是 IOVA**:内核直接当 rknpu_mem_object* 解引用
   (rknpu_job.c:282/339),= MEM_CREATE 40B +0x10 回传的内核对象指针;桩没填故恒 0
2. "chunk 尾无 PC 包"错——trailer 4 包在槽尾(本文 §3)
3. "FUN_002f1fc0 搬 regcmd"错——真搬运在 FUN_004adf40/002f8200
4. "0x70 起是 u16 寄存器表"错——是 FlatBuffers vtable
5. "chunk 值序列模型里搜不到"半错——地址槽是符号 0,几何值就在模型里(§4)
